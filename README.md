# 开屏动画

App 双击启动后显示的开屏动画，兼顾观感和等待加载。用 GLSL 片元着色器写成，在浏览器（或内嵌浏览器内核的桌面壳）里运行，无任何依赖。

这是整个 App 的第一部分。App 的真正前端还没做，目前是占位界面。

## 动画内容

两颗纯黑的水滴从屏幕左下和右上沿缓弧飞入，在中心擦肩而过后顺时针互绕，转速在最后急剧加快，相撞融合成一颗悬浮在正中、表面持续波动的液滴。App 加载完成后，液滴变形展开成 App 窗口，黑色淡出，露出前端界面。

画面只有纯黑和透明两种东西，设计目标是直接显示在透明的桌面窗口上。

| 阶段 | 屏幕上的时长 |
|---|---|
| 弧线入场到擦肩 | 0.6 秒 |
| 互绕到相撞 | 0.5 秒 |
| 液滴悬浮 | 最短 0.6 秒，之后一直等到加载完成 |
| 展开成 App | 0.6 秒 |

加载瞬间完成时，整个开屏最短约 2.3 秒。

## 怎么看

直接双击 `index.html` 用浏览器打开即可，不需要服务器。

想反复看或慢放，打开 `debug.html`：

| 操作 | 作用 |
|---|---|
| 拖进度条 | 定位到任意时刻 |
| `P` 或进度条左侧按钮 | 暂停 / 继续 |
| `←` `→` | 逐帧（每次 0.05 时间线秒） |
| `[` `]` 或倍速滑块 | 0.1× 到 2×，1× 就是成品速度 |
| `R` | 重播 |
| `B` | 切换桌面底图（浅灰、彩色、纯白、深色） |
| 空格 | 让液滴一直停在等待状态，再按一次放行展开 |

## 怎么接入真正的 App

1. 把 `index.html` 里 `#app` 的占位内容换成真正的前端。
2. 删掉文件最后一行模拟加载的定时器，改成在 App 加载完成的地方调用：

   ```js
   window.splash.finish();
   ```

   调用得再早也没关系，动画会等液滴成形（`INTRO_END`）之后才展开；调用得晚，液滴就一直悬浮等待。
3. 套进透明无边框窗口的桌面壳（Electron、Tauri 等）时，删掉 `body` 的渐变背景那一行。它只是浏览器里代替桌面用的底图。

App 窗口的位置由 `MARGIN`（到屏幕边缘的留白）和 `CORNER`（圆角）决定，着色器里黑色展开成的矩形和 `#app` 元素用的是同一组数，改的时候只改这两个常量。

## 怎么调参

可调的量都以带注释的常量写在 `index.html` 着色器的开头。**`debug.html` 是独立的副本，改参数时两个文件要同步改**，否则调试版看到的和成品不一致。

时间线以"时间线秒"书写，屏幕上按 `RATE = 2` 倍速播放，所以代码里的 1 秒在屏幕上是 0.5 秒。

| 想改的感觉 | 常量 | 现值 |
|---|---|---|
| 整体快慢 | `RATE` | 2 |
| 入场弧线的弯曲程度（0 为直线） | `ARC` | 0.40 |
| 入场快慢 | `DEC` | 0.50 |
| 擦肩时离中心多远，也决定中心那一卷的大小 | `PERI` | 0.075 |
| 擦肩后多早向内拐（越接近 1 越早） | `CONV` | 1.7 |
| 末段多转多少、多猛 | `SPIN` | 3.0 |
| 水滴头部大小 | `H0` | 0.034 |
| 拖尾长度（头部半径的倍数） | `TAILLEN` | 4.5 |
| 拖尾模糊强度 | `BLUR` | 0.018 |
| 液滴大小 | `RD` | 0.105 |
| 相撞后的回弹和余振 | `idle()` 里的 `spring`、`lobe` | 见代码 |

长度单位以窗口短边为 1，所以横屏、竖屏窗口里形状比例一致。

## 注意事项

- **深色壁纸上看不见**。水滴和液滴是纯黑的，没有描边和辉光，落在深色桌面上几乎不可见。这个问题还没处理，做透明桌面窗口之前需要决定方案（例如加一圈极细的浅色描边，或按壁纸明暗切换颜色）。在 `debug.html` 里按 `B` 切到深色底图可以看到现状。
- **透明窗口只在 Windows 上验证过**。2026-11-17 接进统一文件页后，在 Windows 的透明 Electron 窗口里实际启动、截屏确认过；Mac 上还没有跑过。
- **入场方向跟着窗口比例走**。水滴沿窗口对角线方向进来，窗口很窄很高时入场会接近竖直。
- **等待时液滴的波动也是二倍速**。`RATE` 作用于整条时间线，包括悬浮阶段。如果觉得等待时晃得太急，需要单独调 `wob()` 和 `BOB`。
- **没有 WebGL 时不播开屏**。浏览器不支持 WebGL 或着色器编译失败时，直接显示 App，不会卡在空白画面。
- **高分屏的开销**。画布按设备像素比渲染，上限 2 倍；每个像素要算两条 28 段的拖尾。集成显卡加 4K 窗口时如果掉帧，先降低 `N` 或像素比上限。
- **开屏只播一次**。结束后画布被移除，要重播只能刷新页面。

## 透明视频版（2026-11-16 导出）

为了在 Mac 的 WKWebView / Safari 里以视频形式播放，动画另外导出成了三段带透明通道的 HEVC 视频，放在 `export/mac_out/`：

| 文件 | 内容 | 帧数 / 时长 |
|---|---|---|
| `intro.mov` | 开场：飞入、互绕、相撞、液滴稳住 | 156 帧 / 2.60 秒 |
| `loop.mov` | 循环：悬浮液滴，首尾相接 | 171 帧 / 2.85 秒 |
| `outro.mov` | 收尾：展开成窗口再淡出到全透明 | 37 帧 / 0.62 秒 |

规格：3840×2160（按 1920×1080 的二倍）、60 帧、`hvc1` 带 alpha、颜色纯黑。播放顺序是 intro → loop 重复任意次 → outro，只能在 loop 播完一整圈时切到 outro。

**导出版和 `index.html` 成品有两处差别**，都是为了让循环能首尾相接（见 `export/build_shader.py` 开头的说明）：液滴波动和浮动的三个频率（1.1、1.7、1.3）统一成 1.10；相撞后的回弹余振在 1.5 秒（屏幕时间）内收到零。其余参数相同。另外开场比网页版长（网页版最早 1.7 秒可展开，视频版固定 2.6 秒后进入循环）。

| 位置 | 内容 |
|---|---|
| `export/build_shader.py` → `splash.frag`、`spec.json` | 从 `index.html` 生成导出用着色器和帧数规格 |
| `export/render.html` + `capture_server.py` | 在浏览器里逐帧渲染透明 PNG，存到 `export/frames/` |
| `export/check_frames.py` | 检查帧数、透明通道、各段衔接和循环首尾 |
| `export/mac_tools/` | Mac 上用的脚本（由 Mac 上的 Claude Code 编写）：`encode.swift` 编码、`inspect.swift` 检查、`test.html` + `serve.py` + `wkplay.swift` 在 WKWebView / Safari 里实际播放并自检，`run_all.sh` 一键跑完 |
| `export/mac_out/` | 取回的三段视频、两份播放自检结果（`wkwebview.json`、`safari.json`）、WKWebView 截图 |
| Mac 上的 `~/Windows互传/splash/` | 同一套源码、PNG 序列、脚本和成片 |

已验证：PNG 序列循环一圈后与第 0 帧逐像素一致；编码后各衔接处的帧差与正常相邻帧相同；在 Safari 27.2 和裸 WKWebView 里三段都播放到结束，四角 alpha 为 0、液滴中心 alpha 253，品红背景从透明区域透出。

未验证：真实的 Tauri 窗口（只测了裸 WKWebView）；窗口本身透明时叠在桌面上的效果；三段视频在页面里实时切换时是否有解码卡顿（只在帧数据层面确认了衔接）。

## 已接进统一文件页（2026-11-17）

统一文件页（`unified/`，Electron）启动时会播这段动画：

- `unified/splash.html` 是动画本体，着色器和参数抄自 `index.html`，只有两处不同：留白和圆角是 0（主窗口是最大化的，黑色直接铺满），没有"淡出"那一段。两边是独立副本，改了 `index.html` 的轨迹或形态要把着色器整段同步过去。
- `unified/main.js` 里的 `createSplash` 先开一个透明、无边框、盖住工作区的窗口播动画（鼠标点击会穿过它，不抢焦点）。主窗口准备好后调用 `splash.finish()`，等黑色铺满，再显示同样是黑底的主窗口，重放界面"从黑里浮出来"的入场动画，然后关掉开屏窗口。
- 从启动到看见界面大约 2.6 秒（液滴成形至少要 1.7 秒）。动画出问题或超过 6 秒，主窗口照常出现。自检模式和截图模式不播开屏。
- 透明视频版没有用上：Electron 是 Chromium 内核，放不了带透明通道的 HEVC。

已验证：Windows 上实际启动，逐帧截屏看到水滴飞入、融合、展开、切到主界面。未验证：Mac 上的效果；深色壁纸上黑色水滴看不清的问题仍然存在。
